# ДсклаД — общий журнал расходов

Страница: `/price-monitoring-krasnodar/expenses/`.

Директор открывает страницу и вводит общий пароль. GitHub-аккаунт для просмотра не нужен. Нажатие «Обновить» загружает последнюю опубликованную версию; автоматическое обновление выполняется раз в три минуты, пока страница открыта и нет неопубликованных изменений.

## Как сохранить изменения для директора

1. Добавьте или измените расходы.
2. Нажмите «Подключить сохранение». Создайте в своём GitHub Fine-grained personal access token только для `price-monitoring-krasnodar`, с разрешением `Contents: Read and write`. В диалоге есть ссылка и инструкция.
3. Вставьте ключ прямо в программу. Не отправляйте его в чат и не передавайте директору.
4. Нажмите «Сохранить для директора». Только после подтверждения GitHub изменения становятся общими.

Ключ остаётся только в памяти вкладки. После перезагрузки или закрытия страницы его нужно вставить снова. До общей публикации записи существуют в памяти вкладки. Перед закрытием программа предупреждает о неопубликованных изменениях. CSV можно скачать как резервную копию.

Если другой пользователь успел опубликовать новую версию, программа остановит сохранение. Выгрузите свой список в CSV, откройте актуальный журнал и повторно внесите изменения. Чужая версия не будет автоматически перезаписана.

## Хранение и перенос

`data.enc.json` содержит общий список, зашифрованный AES-256-GCM с ключом PBKDF2-SHA256 (600000 итераций). Пароль не хранится в исходниках. GitHub видит только зашифрованный файл. Проверка пароля выполняется расшифровкой в браузере. Утрата пароля означает невозможность расшифровать данные. Ротация пароля требует перешифрования файла; старый пароль расшифровывает старые версии из истории GitHub.

Суммы хранятся в целых копейках. В таблице месяц выводится из даты. Расходы из прежней программы перенесены на момент первоначальной публикации. После перехода ведите записи в одной программе: автоматической синхронизации со старой программой нет.

Раздел `expenses` автономный. Исходники, цены, сборка и расписание мониторинга не изменены. При чтении и записи используются HTTPS-запросы к GitHub API. Лимиты и доступность API зависят от GitHub и сети пользователя. При ошибке синхронизации программа явно сообщает об этом и не выдаёт локальные изменения за опубликованные.
